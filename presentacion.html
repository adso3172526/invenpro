Programación Orientada a Objetos — Los 4 Pilares

1. Encapsulamiento

Los datos internos de una clase están protegidos con campos #private. Solo se accede a través de getters/setters con validación.

src/invenpro/domain/Producto.js JS 
class Producto extends BaseEntity {
  #sku;         // Campo privado — no accesible desde fuera
  #nombre;
  #precio;
  #stock;
  #min;

  constructor(data) {
    super(data);
    this.#sku = data.sku || "";
    this.#precio = Number(data.precio || 0);
    this.#stock = Number(data.stock || 0);
    this.#min = Number(data.min || 0);
  }

  // Getter — acceso controlado
  get precio() { return this.#precio; }

  // Setter — con validación (no permite negativos)
  set precio(v) {
    this.#precio = Math.max(0, Number(v || 0));
  }

  // Propiedad calculada derivada del estado interno
  get stockBajo() {
    return this.#stock < this.#min;
  }
}
¿Por qué importa? Nadie puede hacer producto.precio = -100 sin pasar por la validación. Los datos siempre son consistentes.
src/invenpro/core/BaseEntity.js JS 
class BaseEntity {
  #raw;  // Campo privado — almacena todos los datos originales

  constructor(data) {
    this.#raw = Object.assign({}, data || {});
  }

  // setData() solo permite campos autorizados
  setData(data) {
    var allowed = this._allowedFields();
    var keys = Object.keys(data || {});
    for (var i = 0; i < keys.length; i++) {
      if (allowed.length === 0 || allowed.indexOf(keys[i]) !== -1) {
        this.#raw[keys[i]] = data[keys[i]];
      }
    }
    return this;
  }

  toJSON() { return Object.assign({}, this.#raw); }
}

Ejemplo: Factura hereda de BaseEntity JS 
class Factura extends BaseEntity {
  #id;
  #fecha;
  #hora;
  #cajero;
  #metodo;
  #total;
  #items;

  constructor(data = {}) {
    super(data);  // Llama a BaseEntity — hereda toJSON(), getData(), setData()
    this.#id = data.id || "";
    this.#total = Number(data.total || 0);
    this.#items = Array.isArray(data.items) ? data.items : [];
  }

  // Propiedad calculada — lógica específica de Factura
  get cantidadItems() {
    return this.#items.reduce((sum, item) => sum + Number(item.q || 0), 0);
  }
}

3. Polimorfismo

La misma interfaz se usa de diferente manera. GenericHandler maneja cualquier tabla de Supabase con la misma lógica, configurado con datos diferentes.

src/invenpro/store/handlers/GenericHandler.js JS 
class GenericHandler extends IRealtimeHandler {
  constructor(store, eventBus, opts) {
    super(store, eventBus);
    this.key = opts.key;           // "productos", "cajeros", "facturas", etc.
    this.EntityClass = opts.EntityClass;  // Producto, Cajero, Factura, etc.
    this.primaryKey = opts.primaryKey || "id";
  }

  // Mismo método, diferentes comportamientos según la config
  handleInsert(row) {
    var entity = this.EntityClass ? new this.EntityClass(row) : row;
    // ...inserta en el store
  }
}

// ¡Una sola clase maneja TODAS las tablas!
_rtm.registerHandler("productos", new GenericHandler(store, bus, {
  key: "productos", EntityClass: Producto, primaryKey: "sku"
}));
_rtm.registerHandler("cajeros", new GenericHandler(store, bus, {
  key: "cajeros", EntityClass: Cajero, primaryKey: "id"
}));
_rtm.registerHandler("proveedores", new GenericHandler(store, bus, {
  key: "proveedores", EntityClass: Proveedor, primaryKey: "id"
}));

Principios SOLID — Aplicados en el Código Real

S — Single Responsibility (Responsabilidad Única)

Cada clase tiene UNA y solo UNA razón para cambiar.

ViewRefresher

Solo refresca las SQL views (ventas_mes, ventas_cajero, top_productos, ventas_hoy). Nada más.

DetalleRefetcher

Solo refetcha el detalle de un ingreso específico. Nada más.

GenericHandler

Solo maneja eventos INSERT/UPDATE/DELETE de una tabla. Nada más.

FacturaService — delega stock a ProductoService (SRP) JS 
class FacturaService extends BaseService {
  async create(factura, cartItems) {
    // 1. Inserta la factura
    var error = await this._insert("facturas", { ... });
    if (error) return error;

    // 2. Inserta los items
    await this._insert("factura_items", rows);

    // 3. Delega decremento de stock a ProductoService
    //    ¡NO hace stock management directamente!
    if (this._productoService) {
      for (var i = 0; i < cartItems.length; i++) {
        await this._productoService.decrementStock(cartItems[i].sku, cartItems[i].q);
      }
    }
    return null;
  }
}

O — Open/Closed (Abierto/Cerrado)

Abierto para extensión (nuevos servicios), cerrado para modificación (no se toca BaseService).

BaseService — Template Methods (OCP) JS 
class BaseService {
  // Template methods — los hijos los USAN, no los REESCRIBEN
  async _findAll(table) {
    var result = await this.getDb().from(table).select("*");
    if (result.error) throw result.error;
    return result.data || [];
  }

  async _insert(table, data) {
    var result = await this.getDb().from(table).insert(data);
    return this.handleError(table + ".insert", result.error);
  }

  async _update(table, pk, id, data) {
    var result = await this.getDb().from(table).update(data).eq(pk, id);
    return this.handleError(table + ".update", result.error);
  }

  async _rpc(fn, params) {
    var result = await this.getDb().rpc(fn, params);
    return this.handleError("rpc." + fn, result.error);
  }
}
ProductoService — extiende sin modificar BaseService JS 
class ProductoService extends BaseService {
  async getAll() {
    if (this.repo) return this.repo.findAll();
    var data = await this._findAll("productos");  // ← template method
    return this._camelize(data).map(function(d) { return new Producto(d); });
  }

  async create(producto) {
    var row = this._snakify({ sku: producto.sku, nombre: producto.nombre, ... });
    return this._insert("productos", row);  // ← template method
  }

  async update(sku, updates) {
    return this._update("productos", "sku", sku, this._snakify(updates));
  }

  async decrementStock(sku, qty) {
    return this._rpc("decrement_stock", { p_sku: sku, p_qty: qty });  // ← template method
  }
}

L — Liskov Substitution (Sustitución de Liskov)

Las subclases pueden reemplazar a sus padres sin romper el contrato. IngresoRepository retorna una entidad Ingreso — misma interfaz que BaseRepository.

IngresoRepository — cumple contrato de BaseRepository + extiende JS 
class IngresoRepository extends BaseRepository {
  constructor(db) {
    super("ingresos", "id", function(row) {
      var raw = Helpers.camelize(row);
      raw.detalle = raw.ingresoDetalle || [];
      delete raw.ingresoDetalle;
      return new Ingreso(raw);  // ← Retorna entidad Ingreso
    }, db);
  }

  // Métodos extra — extiende sin romper
  async findAllWithDetalle() { ... }
  async findDetalleByIngresoId(id) { ... }
  async insertDetalle(rows) { ... }
}
Liskov en acción: Cualquier código que use BaseRepository puede usar IngresoRepository sin cambios. Los métodos findAll(), findById(), create(), update(), remove() funcionan igual.

I — Interface Segregation (Segregación de Interfaces)

Cinco interfaces pequeñas y específicas. Ninguna clase es forzada a implementar métodos que no necesita.

D — Dependency Inversion (Inversión de Dependencias)

Todas las dependencias se inyectan en el constructor. Cero fallbacks window.* en business logic.

AppController — DI estricta JS 
class AppController {
  constructor(deps) {
    deps = deps || {};
    this._authUseCase = deps.authUseCase || null;  // ← Inyectado, no hardcodeado
    this._storage = deps.storage || window.localStorage;
  }

  async login(usuario, pass) {
    if (!this._authUseCase) throw new Error("AuthUseCase no inyectado");
    return this._authUseCase.login(usuario, pass);
  }
}
data.js — Wiring centralizado (único lugar con new) JS 
// Repositories — DB inyectada
var productoRepo = new ProductoRepository(db);
var facturaRepo = new FacturaRepository(db);

// Services — DB + repos inyectados
var authService = new AuthService(db, { helpers: Helpers, repo: usuarioRepo });
var productoService = new ProductoService(db, { helpers: Helpers, repo: productoRepo });
var facturaService = new FacturaService(db, { productoService: productoService, repo: facturaRepo });

// Controllers — servicios inyectados
var appController = new AppController({ authUseCase: authUseCase });
window.appController = appController;  // ← Punto de acceso único
Sin DI (antes): new InvenPro.AppController() — hardcodeado, no testeable.
Con DI (ahora): new AppController({ authUseCase }) — inyectado, testeable, flexible.

data.js — La Capa de Wiring

Regla: data.js es el ÚNICO archivo que crea instancias con new. Todo lo demás recibe dependencias por constructor.
  • Crea window.MOCK (DataStore instance)
  • Crea window.DB (service layer)
  • Crea window.appController (AppController con DI)
  • Crea EventBus, RealtimeManager, ViewRefresher, DetalleRefetcher con DI
  • Registra handlers para todas las tablas
  • Expone globals backward-compat: window.camelize, window.snakify, etc.
